# v0.8.0：新增检测、下载保护与完整标题

## 升级

Windows 和 NAS 端一起更新到 v0.8.0。停止执行端容器后，把增量包 app 里的五个 Python 文件复制到现有 app，保留 .env、state、config/regions.json 和自己的 Compose，再启动。无需重新创建已有硬链接。

本次发布未部署 NAS，也未修改媒体。

## 日常补充

1. 在 Windows 载入保存的任务，填写密钥并连接。
2. 点击“检测待补充（只读）”。程序重新扫描实际文件，自动筛选“待创建”；已有硬链接仍在全部视图里，不重复创建。删除过入口也会被列为需要补充，不能将待补充简单等同于刚下载。
3. 查看汇总中的暂缓、冲突和跳过项目。切换“查看”筛选只影响显示；创建执行该次完整预览中所有待创建项，确认窗口会列出数量。
4. 确认这是修改操作后执行，完成后再次只读扫描核对。

## 下载保护

默认静置300秒，可填写0～86400秒。近期修改、扫描间大小或时间变化、同目录临时下载标记、空媒体/配套文件会导致该目录文件组暂缓，避免视频和封面只处理一半。临时文件及临时目录始终排除；0只关闭静置时间，不关闭临时与空文件保护。

支持常见 .part、.partial、.crdownload、.download、.tmp、.!qB、.!ut、.aria2、.bc! 名称。保护依据文件状态作启发式判断，并非下载器完成通知，无法保证预分配或暂停中的下载已完成。跨扫描变化记录保存在执行端内存中，重启后不保留；静置时间和临时文件检查仍有效。可先等待下载工具明确完成再整理，不要仅靠把秒数改为0来绕过暂缓。

## 在 Emby 显示完整标题

勾选“完整标题：新增 NFO（不覆盖已有）”，重新扫描。预览会列出操作类型为“新增 NFO”的项目，标题栏显示原始视频完整主名（去除扩展名），支持双击查看与 CSV 导出。

例如原件为一个完整长标题.mp4，入口视频仍使用兼容长度的名称.mp4，在入口视频旁新增同名 .nfo；NFO 内容使用原始完整标题，不需要把视频改回长名。NFO 是独立的小文本文件，会占用少量空间，不是视频硬链接，也不改写原视频内容。

已建立视频入口也能单独补充缺失 NFO。已有目标 NFO、已有同名源 NFO 保留，不覆盖、不合并；源 NFO 按原有方式建立硬链接。同主名多个视频竞争同一个 NFO 时列为元数据冲突，不猜测标题。生成 NFO 使用独占新建，执行时发现外部新文件则停止并保留对方文件。

Emby 的 NFO 解析器支持 title 与 originaltitle 字段，见 [官方项目解析器](https://github.com/MediaBrowser/NfoMetadata/blob/master/NfoMetadata/Parsers/BaseNfoParser.cs)。在媒体库设置确认 NFO 元数据读取启用，并对一部测试影片刷新元数据。不要将“NFO 保存”误认为“NFO 读取”。程序不会调用 Emby API、自动刷新或修改现有影片元数据；不同库类型、现有锁定元数据及旧版本读取效果，仍需在你的 Emby 4.5.4 测试。

## 保持的边界

区域权限、预览失效、显式创建确认、硬链接身份核验保持。原件不删除、不改名、不改写，已有入口不自动改名。不自动定时写入，不清理旧入口，不回退复制视频。NFO 只在已授权的入口范围内新增。
