# v0.9.0 使用与升级：进度、安全停止、恢复查看和密钥文件

## 升级方式

Windows 与 NAS 执行端一起更新到 v0.9.0。等现有任务结束后停止容器，将增量包 app 下六个 Python 文件覆盖到现有 app（包含新增 job_status.py），保留 .env、state、config/regions.json 和自己的 Compose，再启动容器。客户端运行新版 exe。无需重新建立已有硬链接。

本次只生成发布文件，未部署 NAS，也未操作媒体。

## 连接密钥不用每次手填

在密钥行点击“选择密钥文件”，选择你保存的 UTF-8 文本文件，内容可以是：

- 仅一行 NAS 实际使用的连接密钥，至少24个字符。
- 现有 .env，包含唯一 AGENT_TOKEN=实际密钥；支持值两侧的单引号或双引号。

必须与 NAS 当前使用的值一致；不要误选新生成但未部署的另一份 .env。选好后客户端只保存文件路径，启动后点击连接时自动读取；保存任务也会记录该任务的密钥文件位置。配置、恢复记录和日志不保存密钥内容。

文件是明文，请放在你自己可访问的位置，不放入代码仓库、报告或共享给他人的文件夹。程序不会为你创建或复制密钥文件，不改变原文件权限。文件丢失或格式错误会明确提示，不会悄悄改用旧密钥。文件里的密钥更换后，连接检查会使旧预览失效并要求重新连接。点击“改为手动输入”即可取消文件模式并清空内存中的旧值。

## 进度与安全停止

创建后显示已处理/计划项数、进度条、当前文件及硬链接/NFO计数。硬链接是文件系统操作，不是上传视频，因此进度按文件项计数，不显示虚假的传输速度或字节进度。

点击“当前文件完成后停止”并确认。NAS 收到请求后，当前文件会处理到结束，然后不再开始下一项。已创建目录、硬链接和 NFO 全部保留，不回滚、不删除。如果请求到达时全部文件已完成，结果仍是全部完成。

请求发送失败或响应丢失时，不能认定已经停止。查看原任务状态或再次请求，不要直接关闭容器。当前文件若受文件系统调用阻塞，停止也需要等待该调用返回。

停止后继续整理须重新只读扫描、确认剩余项，再明确创建；恢复查看不会续跑或补创建。

## 断线与重开软件后恢复

1. 点击连接。可使用保存的密钥文件，无需重新输入密钥。
2. 点击“恢复查看最近任务（只读）”，按本机记录的提交编号/任务编号查询原任务。
3. 若本机没有记录，打开 NAS 任务历史，选中任务后点击“恢复查看选中任务”。
4. 原任务仍运行则继续显示进度，可请求安全停止；已经结束则显示原结果。不会自动调用创建接口。

客户端在提交前保存不含密钥的恢复凭据，因此即使创建请求已到达 NAS 但响应丢失，也可按提交编号查询。查询不到、NAS重启且缺少结束记录、网络中断等情况均显示状态未知，不能当作成功，也不能自动重试创建。服务历史只返回最近200条任务；更早任务可能需要只读扫描复核。

NAS 在文件处理边界记录进度。异常断电或执行中崩溃时，最近一项的实际状态可能领先于记录；重启后未完成记录会标为未知。重新只读扫描才是复核实际文件的依据。

关闭查看窗口不会停止 NAS；关闭前会提醒，重新打开可恢复查看。正在执行其他只读操作时先等待该操作完成。

## 结果分类

| 分类 | 含义与下一步 |
| --- | --- |
| 全部完成 | NAS 确认计划项均已处理且没有错误；可只读扫描复核 |
| 部分完成 | 已创建至少一个文件后停止或失败；保留完成内容，重扫剩余项 |
| 未创建文件 | 已确认任务结束且没有新增文件；可能已建立空目录，检查停止原因或错误 |
| 状态未知 | 无法确认实际结束状态；恢复查看或只读扫描，不自动重试 |

如果 NFO 新建后写入中途失败，结果按部分完成处理，并提示可能有未完整写入的 NFO；程序不删除或覆盖它。硬链接创建后身份核验失败也不会误报全部完成。

## 保存位置

Windows：%LOCALAPPDATA%/EmbyLinkStudio 下 agent_settings.json（偏好和密钥文件路径）、tasks.json（任务偏好）、recovery.json（最多200条提交凭据）。都不保存连接密钥内容。

NAS：state/history.jsonl 保存任务与进度事件，state/created.jsonl 保存已创建内容记录。升级时保留 state，不能用空目录替换。
