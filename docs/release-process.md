# 安装包发布流程

普通代码提交只运行测试，不自动发布安装包。

需正式发布时，由维护者审查明确的源码提交，并更新 release-request.json 中的版本与完整提交 SHA，同时准备 docs/releases/v版本.md 中文说明。仅 main 上该申请文件的变化或显式手动运行，才触发 release.yml。

流水线从指定提交检出源码，核对版本，重新运行测试与隐私检查，构建 Windows 程序和 NAS 包，再运行程序启动自检及哈希校验。只上传明确列出的五个文件，不携带本地 .env 或 state。发布使用 GitHub 提供的本次任务令牌，不需要在仓库保存个人访问令牌。

已有同名 Release 会阻止上传，不覆盖、不删除。上传失败可能留下草稿，须检查现场后再决定如何继续。
普通候选构建工作流 build.yml 仍不上传文件。

v0.11.1 的源提交已通过 Windows/Linux × Python 3.12/3.13 四组 CI。首次安装包发布由用户明确要求；后续发布同样应在维护者确认发行范围之后更新申请，不因一般代码提交而擅自发布。
